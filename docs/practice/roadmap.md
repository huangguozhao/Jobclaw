# JobClaw 训练路线图

## 路线设计

这条路线不是按成品目录机械拆分，而是按“每期可独立验收、复杂度逐步增加”的顺序组织。

```text
工程基线
  → 岗位目录 → 草稿审核 → 用户权限
  → 多模块运行时 → 统一消息 → WebSocket
  → 模型供应商 → LLM 与工具 → 多 Agent 路由
  → 会话记忆 → 用户画像
  → 多来源采集 → AI 清洗发布 → 个性化推荐
  → 计划任务 → 外部 IM
  → 动态配置与可观测性 → 安全可靠性毕业项目
```

## 四个里程碑

### M1：可用的岗位产品（第 00～03 期）

能交付一个有公开页面、运营后台和权限保护的普通 Web 应用。重点训练业务建模、数据库、接口、前端和事务；这个阶段不引入 AI 复杂度。

### M2：可扩展的智能体运行时（第 04～09 期）

建立模块接口、渠道适配、实时消息、多模型、工具执行和多智能体路由。重点训练依赖方向、适配器、事件驱动和失败语义。

### M3：真正的求职智能体（第 10～16 期）

加入记忆、画像、岗位采集、AI 清洗、推荐、调度和外部渠道。重点训练不确定输出的治理、异步流程、证据链和用户隐私。

### M4：生产化交付（第 17～18 期）

完成动态配置、链路监控、安全、故障恢复和压测。重点训练从“功能能跑”走向“系统可信”。

## 能力评分

每个里程碑结束时，从 1～5 分评估以下维度，并给出代码、测试或运行证据：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 需求分析 | 直接编码 | 能识别主要歧义 | 能量化目标并控制范围 |
| 领域建模 | 表即业务 | 能表达状态和不变量 | 模型能支撑变化且语言一致 |
| 模块设计 | 依赖混乱 | 主要职责清楚 | 接口小、实现深、测试自然 |
| 编码实现 | 仅正常路径 | 处理常见异常 | 并发、恢复和演进均有依据 |
| 测试 | 只测方法 | 覆盖主要业务场景 | 测试穿过接口且抗重构 |
| 排障 | 靠猜和重启 | 能用日志定位 | 能从指标、追踪和实验缩小原因 |
| 交付 | 本机可跑 | 文档可复现 | 可发布、可回滚、可恢复 |

## 节奏建议

每期用一个短迭代完成。第一天只做澄清和设计，设计评审通过后再编码。最后一天固定做验收和复盘。若一期超过建议周期，优先缩小范围并保留闭环，不通过堆砌未完成代码追进度。

## 参考源码使用时机

1. 需求阶段禁止查看对应成品实现。
2. 技术设计完成后，可以只查看 `coach-reference.md` 中列出的模块名称，验证边界是否遗漏。
3. 第一版通过验收后，再阅读成品源码并写差异复盘。
4. 不以“与成品一致”为正确标准；以满足需求、可解释取舍和通过验收为标准。
