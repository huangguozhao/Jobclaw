# 第 11 期：用户画像与模型偏好

**依赖**：第 10 期  
**目标**：通过渐进对话建立可确认的求职画像，并按用户偏好选择模型与响应方式。

## 业务背景

个性化推荐需要了解用户的教育背景、技能、目标城市、岗位方向和工作偏好。一次性长表单体验差，完全依赖模型猜测又可能写入错误事实。

## 用户故事

- 作为新用户，我会被逐步询问缺失的关键资料，而不是一次填完长表单。
- 作为用户，我能查看、更正和删除自己的画像。
- 作为用户，我能为不同能力选择模型，并配置自己的供应商凭据。
- 作为用户，我能知道哪些信息来自本人确认，哪些是系统推断。

## 业务规则

1. 用户画像至少区分稳定个性与职业偏好、教育技能经历、基础渠道信息三类内容。
2. 每条可变画像事实记录来源、更新时间和确认状态；模型推断不得覆盖用户已确认事实。
3. 首次对话只询问完成当前服务所必需的信息；群聊不采集私密画像。
4. 用户可跳过问题，系统不得因此阻止所有功能；需要画像的能力可明确降级。
5. 用户级模型偏好覆盖系统默认，格式与第 07 期一致；凭据展示时脱敏。
6. 删除画像后，后续模型调用不再注入已删除内容；原始审计保留策略需在隐私说明中明确。
7. 画像文件或记录按用户隔离，路径和查询参数不能造成越权读取。

## 范围外

自动读取完整简历、行为推荐学习、跨用户画像分析和招聘方画像。

## 验收场景

- Given 新用户缺少目标城市，When 请求岗位推荐，Then 系统只追问必要信息并允许跳过。
- Given 模型推断用户偏好上海但用户确认杭州，When 更新画像，Then 杭州成为有效事实。
- Given 群聊消息包含个人经历，When 处理，Then 不自动写入个人画像。
- Given 用户删除某项技能，When 下一次构建 Prompt，Then 不再包含该技能。
- Given 用户配置个人文本模型，When 调用，Then 优先使用个人配置且接口不泄露完整密钥。

## 非功能要求

个人画像访问有审计；敏感字段支持删除；Prompt 注入有大小上限；采集流程可中断和恢复。

## 设计评审问题

- 画像是文档、结构化记录还是二者组合？谁是事实来源？
- 如何处理相互矛盾的画像事实？
- “删除”与审计留存、模型缓存之间如何协调？

## 交付物

画像模型、渐进采集流程、确认与更正接口、模型偏好页面、Prompt 注入策略、隐私与越权测试。
