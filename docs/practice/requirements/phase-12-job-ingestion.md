# 第 12 期：多来源岗位采集

**依赖**：第 11 期  
**目标**：接收文本、网页、文件和图片来源，异步产出可追踪的原始岗位记录。

## 业务背景

岗位信息来自公众号文章、招聘网页、Excel、CSV、Markdown、图片和人工粘贴。读取方式不同，但后续清洗需要一致的来源记录和证据。

## 用户故事

- 作为运营人员，我能提交一个或多个来源并立即得到采集任务编号。
- 作为运营人员，我能查看每个来源的进度、结果、错误和原始证据。
- 作为运营人员，我能对失败来源重试，而不重复处理已经成功的来源。
- 作为系统，我能限制危险文件和不可信网页。

## 业务规则

1. 采集任务与岗位来源分开建模，一个任务可以包含多个来源。
2. 来源类型至少支持纯文本、URL、CSV、Excel 和图片；每类通过独立适配器读取为统一原始记录。
3. 提交后异步执行，状态至少包含待处理、执行中、部分成功、成功、失败和取消。
4. 每条原始记录保留来源标识、内容、采集时间和可定位证据；失败包含可理解原因。
5. 单个来源失败不阻止其他来源完成；任务最终状态反映部分成功。
6. 重试只处理可重试失败，并保证成功记录不重复。
7. URL 采集限制协议、重定向、响应大小和内网地址；文件限制类型、大小、工作表和行数。
8. 采集阶段不直接发布正式岗位。

## 范围外

结构化岗位字段的 AI 提取、自动发布、网站登录绕过和验证码处理。

## 验收场景

- Given 一个包含两个工作表的 Excel，When 采集，Then 生成带来源定位的原始记录。
- Given 任务中一个 URL 超时、一个 CSV 成功，When 完成，Then 状态为部分成功且成功数据保留。
- Given 对失败来源重试，When 第二次成功，Then 不重复创建之前成功的记录。
- Given URL 指向本机或内网地址，When 提交，Then 安全校验拒绝访问。
- Given 超大文件，When 上传，Then 在资源耗尽前被拒绝并返回限制说明。

## 非功能要求

任务进度可查询；文件读取流式处理；异步执行有并发上限、超时和取消；临时文件最终清理。

## 设计评审问题

- 统一原始记录的最小接口是什么？
- 任务状态由事件推导还是直接更新？如何避免并发覆盖？
- 网页正文提取失败时是否保留原始 HTML？保留多久？

## 交付物

任务与来源模型、五类读取适配器、异步执行、进度接口与页面、重试取消、安全测试和样例文件。
