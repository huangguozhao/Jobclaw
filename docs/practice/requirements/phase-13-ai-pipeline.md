# 第 13 期：AI 清洗、草稿与发布流水线

**依赖**：第 12 期  
**目标**：把原始记录批量提取为有证据的岗位草稿，并接入审核发布流程。

## 业务背景

原始招聘内容常包含多岗位、表格、噪声和不完整字段。模型能够辅助结构化提取，但结果可能截断、幻觉或合并错误，必须经过校验和审核。

## 用户故事

- 作为运营人员，我能从采集任务启动结构化提取并查看实时进度。
- 作为审核人员，我能看到每个字段对应的原文证据。
- 作为运营人员，我能修正、驳回或发布提取出的草稿。
- 作为系统，我能处理模型截断、批次失败和重复岗位。

## 业务规则

1. 原始记录按可配置批次提取，输出使用结构化契约并做严格校验。
2. 一个原始记录可产生零个、一个或多个岗位草稿；不得强迫模型“至少生成一个”。
3. 每个草稿保留来源、证据片段、提取版本和模型调用关联 ID。
4. 模型输出非法时允许有限修复或重试；达到上限后标记人工处理，不丢弃原文。
5. 超长来源需分块并处理跨块重复；最终汇总记录请求数、截断次数和失败数。
6. 入草稿库前执行字段规范化和候选去重，但低置信度去重不得自动删除。
7. 自动发布默认关闭；只有满足明确质量门槛且管理员开启后才能启用。
8. 最终发布复用第 02 期的状态和事务规则。

## 范围外

模型微调、OCR 模型训练、完全无人审核和推荐排序。

## 验收场景

- Given 一段包含三个岗位的文本，When 提取，Then 生成三条草稿并能定位原文证据。
- Given 模型返回非法 JSON，When 修复和重试仍失败，Then 来源进入人工处理且原文可查看。
- Given 模型响应被截断，When 系统检测，Then 记录截断并按策略重试或分块。
- Given 两个块提取出同一岗位，When 汇总，Then 标记重复候选而不是静默生成两条正式岗位。
- Given 自动发布开关关闭，When 提取质量再高，Then 结果仍进入待审核状态。

## 非功能要求

批次大小与并发可配置；模型调用可取消；进度可重启恢复；所有自动决策可追踪到版本和证据。

## 设计评审问题

- 如何定义“有证据的字段”，证据保存文本还是位置？
- 结构化提取应该一次生成整条岗位还是按字段分步？
- 模型版本或 Prompt 改变后，旧草稿如何重跑和比较？

## 交付物

提取契约、批处理模块、校验与修复、证据模型、草稿集成、进度页面、故障恢复测试和质量报告。
