# 第 07 期：多模型供应商

**依赖**：第 06 期  
**目标**：让系统按能力和用户配置选择模型，并隔离不同供应商差异。

## 业务背景

团队需要接入 OpenAI 兼容接口、阿里和 Anthropic 等供应商。不同用户可能使用不同凭据，同一用户也可能为文本、视觉和嵌入选择不同模型。

## 用户故事

- 作为管理员，我能配置供应商地址、凭据和可用模型，并测试连接。
- 作为系统，我能按用户和能力类型解析出正确模型。
- 作为开发者，我能增加一种供应商适配器，而不修改业务智能体。
- 作为用户，供应商不可用时能得到明确、可恢复的错误。

## 业务规则

1. 模型引用采用稳定格式，能唯一表达供应商和模型名称。
2. 能力类型至少区分文本与视觉；设计需说明未来扩展图片、语音和嵌入的方式。
3. 用户配置优先于系统默认配置；缺失时按明确层级回退，不允许随机选模型。
4. 凭据加密或安全保存，列表接口和日志只显示脱敏值。
5. 更新供应商配置后，新请求使用新配置；正在执行的请求行为必须被定义。
6. 供应商错误转换为统一错误类别：认证失败、限流、超时、不可用、请求非法和未知错误。
7. 测试环境提供本地假模型，验收不依赖真实付费 API。

## 范围外

复杂成本路由、自动故障转移、模型效果评测和按量计费。

## 验收场景

- Given 用户配置了文本模型，When 发起文本请求，Then 使用指定供应商和模型。
- Given 用户未配置视觉模型但系统有默认值，When 解析视觉模型，Then 使用系统默认。
- Given 模型引用格式非法，When 保存配置，Then 请求被拒绝并指出错误字段。
- Given 供应商返回限流，When 调用，Then 上层收到统一的可重试错误。
- Given 查询供应商列表，When 查看响应和日志，Then 看不到完整凭据。

## 非功能要求

模型解析过程不进行网络调用；并发读取配置线程安全；适配器契约包含超时和取消语义。

## 设计评审问题

- 供应商与模型能力的关系如何表达？
- 配置热更新采用不可变快照还是原地修改？
- 业务层应该得到供应商 SDK 对象还是项目自有的模型接口？

## 交付物

供应商模型、模型解析模块、至少两个本地适配器、配置后台、连接测试、错误映射测试和安全检查。
