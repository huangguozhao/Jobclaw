# 第 00 期：工程基线与可运行骨架

**目标**：建立所有后续迭代共用的可构建、可启动、可诊断基线。

## 业务背景

团队准备开发 JobClaw。新成员必须能在一台干净的开发机上快速启动系统，并明确本地开发与集成环境的差异。当前阶段不实现具体业务。

## 用户故事

- 作为开发者，我能用一条文档化命令构建后端并运行测试。
- 作为开发者，我能分别启动后端和前端，并确认它们可用。
- 作为运维人员，我能通过健康接口判断进程是否具备服务能力。
- 作为安全负责人，我不会在仓库中看到真实密钥和个人配置。

## 功能要求

1. 后端使用 Java 21 和 Maven Wrapper，前端使用 TypeScript、React 与固定的包管理器。
2. 提供本地开发配置，默认使用文件型数据库，不要求安装外部数据库。
3. 配置可由环境变量覆盖，并提供不含秘密的示例文件。
4. 健康接口至少返回状态、服务版本和当前环境；不得泄露密钥、数据库口令和绝对用户目录。
5. 前端提供一个可访问的占位首页，并能调用后端的只读状态接口。
6. README 写清系统要求、初始化、启动、测试和常见故障。

## 范围外

登录、岗位、聊天、模型调用、生产部署和 CI/CD。

## 验收场景

- Given 一台仅安装 Java 21、Node 和 Git 的机器，When 按 README 操作，Then 后端与前端均能启动。
- Given 后端已经启动，When 访问健康接口，Then 返回 HTTP 200 和可解析的健康状态。
- Given 缺少必要配置，When 启动系统，Then 启动失败并明确指出缺少的配置项。
- Given 搜索整个仓库，When 检查敏感信息，Then 不存在真实 API Key、Cookie 或数据库密码。
- Given 执行后端测试和前端构建，Then 命令以成功状态结束。

## 非功能要求

首次完整构建失败时必须保留可定位的错误信息；日志使用 UTF-8；Windows、macOS 或 Linux 至少选择两个平台说明差异。

## 设计评审问题

- 哪些配置是启动必需，哪些只是能力开关？
- 健康状态应区分“进程存活”和“可接收业务请求”吗？
- 前后端开发时如何处理地址和跨域？

## 交付物

工程骨架、配置示例、健康接口、占位首页、启动文档、自动化冒烟测试和验收报告。
