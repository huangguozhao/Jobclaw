# 第 09 期：多 Agent 注册、意图与路由

**依赖**：第 08 期  
**目标**：根据用户意图把消息交给合适的业务智能体，并维持多轮会话连续性。

## 业务背景

JobClaw 将出现通用问答、岗位采集、岗位推荐、偏好设置和计划任务等智能体。用户不应每句话都手工选择智能体，但必须能够查看和纠正系统选择。

## 用户故事

- 作为开发者，我添加一个业务智能体后，它能被注册和发现。
- 作为用户，我可以自然表达目标，由系统选择合适智能体。
- 作为用户，我可以查看当前智能体、主动切换或重置会话绑定。
- 作为系统，当识别不确定或智能体失败时，我能安全回退。

## 业务规则

1. 每个智能体有唯一标识、描述、支持意图、权限、优先级和可用状态。
2. 注册时发现重复标识必须启动失败或明确拒绝，不能依赖注册顺序覆盖。
3. 意图识别先使用确定性规则，再在必要时调用模型；输出包含意图、置信度和理由。
4. 同一会话可绑定当前智能体；普通追问沿用绑定，明显切换目标时重新识别。
5. 系统命令至少支持帮助、智能体列表、查看当前、切换和重置，命令处理不调用模型。
6. 无匹配、低置信度、无权限或智能体不可用时，采用可解释回退。
7. 智能体异常不得丢失终止响应，也不得污染其他会话的绑定。

## 范围外

多个智能体并行协作、自动任务分解和长期记忆。

## 验收场景

- Given 两个支持不同意图的智能体，When 用户表达清晰目标，Then 路由到正确智能体。
- Given 用户随后发送省略主语的追问，When 无切换信号，Then 沿用当前智能体。
- Given 输入查看当前智能体命令，When 执行，Then 不调用模型并返回绑定信息。
- Given 目标智能体要求会员权限，When 普通用户请求，Then 不执行并说明可用选择。
- Given 两个智能体注册相同标识，When 启动，Then 系统明确失败并指出冲突双方。

## 非功能要求

路由决策有结构化日志；规则识别目标耗时 20ms 内；会话绑定线程安全并按用户隔离。

## 设计评审问题

- “意图”和“智能体”是一对一还是多对多？
- 什么条件触发重新识别，如何防止频繁跳转？
- 回退到通用模型是否会掩盖业务错误？

## 交付物

智能体契约、注册表、分类器、路由器、会话绑定、命令系统、三个示例智能体和端到端测试。
