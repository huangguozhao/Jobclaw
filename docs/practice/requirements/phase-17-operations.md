# 第 17 期：动态配置与可观测性

**依赖**：第 16 期  
**目标**：让关键能力可安全配置，并能从一次用户消息追踪到模型、工具和响应。

## 业务背景

系统已经包含数据库、模型、工具、智能体、调度和多个渠道。仅靠普通日志难以回答“为什么这条消息失败”“本月哪个模型最贵”“配置修改后何时生效”。

## 用户故事

- 作为管理员，我能查看和修改允许动态变更的全局配置。
- 作为管理员，我能在保存前测试模型供应商配置，并安全回滚错误配置。
- 作为运维人员，我能查看请求量、错误率、耗时、模型用量和失败阶段。
- 作为开发者，我能用一个关联 ID 追踪完整消息链路。

## 业务规则

1. 配置项分为启动配置、可热更新配置和用户配置；不同类别有明确生效时机。
2. 配置更新先校验，再以版本化快照生效；失败不破坏当前可用配置。
3. 关键配置变更记录操作者、前后版本、时间和结果；敏感值只记录是否变化。
4. 一次交互共享关联 ID，并关联渠道消息、路由决策、智能体、模型请求、工具和响应。
5. 模型监控至少记录供应商、模型、耗时、token 或等价用量、结束原因和错误分类。
6. 健康、就绪和存活状态含义不同；非关键渠道故障不必让整个进程退出就绪状态，策略需说明。
7. 指标标签禁止直接使用用户输入、完整用户 ID 或高基数字段。

## 范围外

采购商业监控平台、全链路 OpenTelemetry 集群和自动成本结算。

## 验收场景

- Given 一份非法供应商配置，When 管理员保存，Then 当前配置继续可用且返回校验原因。
- Given 合法配置版本生效，When 新请求到达，Then 使用新版本；旧请求行为明确。
- Given 一次工具调用失败，When 按关联 ID 查询，Then 能看到渠道、路由、模型和工具阶段。
- Given 查看模型用量概览，When 按时间和模型筛选，Then 汇总与明细一致。
- Given 日志和指标导出，When 搜索敏感数据，Then 不包含密钥和完整 Prompt 中的敏感字段。

## 非功能要求

监控本身失败不得阻塞主请求；记录写入有容量策略；配置读取不成为高频调用瓶颈。

## 设计评审问题

- 哪些信息适合日志、指标、追踪或审计，各自保留多久？
- 配置发布需要全量事务还是按供应商独立版本？
- 如何测量流式响应的首字延迟和总耗时？

## 交付物

配置分类与版本、管理页面、调用记录、指标看板、健康策略、链路演示、脱敏测试和故障演练报告。
