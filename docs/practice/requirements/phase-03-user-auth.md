# 第 03 期：用户、认证与权限

**依赖**：第 02 期  
**目标**：区分匿名用户、普通用户、会员和管理员，并保护后台与个人数据。

## 业务背景

公开岗位允许匿名查看，但个人偏好、聊天、渠道绑定和运营后台必须识别用户。系统未来还会按会员等级开放不同智能体能力。

## 用户故事

- 作为访客，我能体验公开岗位，并可创建临时会话。
- 作为注册用户，我能登录、退出并查看自己的资料。
- 作为用户，我只能读取和修改自己的个人数据。
- 作为管理员，我能管理用户角色，但不能误操作自己的最后一个管理员权限。

## 业务规则

1. 系统至少支持访客、普通用户、会员和管理员四种业务身份。
2. 认证凭据必须可失效，并有明确过期时间；退出后旧凭据不可继续访问受保护资源。
3. 后端独立完成授权判断，前端隐藏菜单不能作为权限控制。
4. 用户只能访问自己的偏好、订单、渠道绑定和使用记录。
5. 角色变更需要管理员权限并留下审计记录；系统必须始终保留至少一个可用管理员。
6. 接口返回和日志不得包含口令、完整令牌或第三方密钥。

## 范围外

第三方 OAuth、完整支付系统、组织与租户模型、细粒度策略语言。

## 验收场景

- Given 未登录用户，When 访问后台接口，Then 返回未认证响应。
- Given 普通用户 A，When 使用自己的凭据访问用户 B 的资源，Then 返回无权限且不泄露资源是否存在。
- Given 管理员，When 调整用户角色，Then 变更生效并写入审计记录。
- Given 系统仅剩一个管理员，When 尝试取消其管理员角色，Then 操作被拒绝。
- Given 用户退出，When 复用原凭据，Then 受保护接口拒绝请求。

## 非功能要求

认证失败不输出敏感差异；权限测试覆盖横向越权和纵向越权；所有个人数据查询显式带用户范围。

## 设计评审问题

- 访客身份何时升级为正式用户，历史数据如何归并？
- 角色是用户属性还是独立授权关系？
- 会话凭据选择服务端会话还是自包含令牌，各自如何撤销？

## 交付物

用户模型、认证流程、授权规则、个人中心最小页面、管理员用户页、审计证据和安全测试。
