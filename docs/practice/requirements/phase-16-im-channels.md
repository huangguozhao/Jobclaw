# 第 16 期：外部 IM 渠道接入

**依赖**：第 15 期  
**目标**：在不改业务链路的情况下接入至少两个真实或沙箱 IM 渠道。

## 业务背景

用户希望在微信、钉钉或飞书中使用 JobClaw。平台在认证、消息格式、流式更新、媒体下载和群聊身份方面差异显著。

## 用户故事

- 作为用户，我能绑定一个外部渠道身份并与智能体对话。
- 作为渠道所有者，我能添加机器人配置并限定谁可以使用。
- 作为用户，我能发送文本以及渠道支持的图片或文件。
- 作为系统，我能在平台限制内提供流式或渐进式响应。

## 业务规则

1. 每个渠道实现第 05 期的统一接口，平台 SDK 对象不得进入核心业务。
2. 渠道账号配置与渠道身份绑定分开；一个机器人可以服务多个允许的用户。
3. 机器人范围至少支持仅所有者、已登录用户、会员和公开四种策略。
4. 私聊可使用个人画像和偏好；群聊默认不读取或修改个人敏感配置。
5. 平台回调或长连接消息必须验签、去重并校验时间窗口。
6. 媒体先验证声明类型、实际类型和大小，再保存到隔离目录；临时文件按策略清理。
7. 不支持原生流式的平台采用可接受的降级方式，且不频繁刷屏。
8. 渠道解绑后停止主动推送并撤销相关访问能力。

## 范围外

绕过平台审核、个人号非官方自动化、富文本编辑器和所有平台一次接完。

## 验收场景

- Given 两个渠道收到语义相同的私聊消息，When 处理，Then 进入同一业务链路并返回等价结果。
- Given 未签名或过期回调，When 到达，Then 在业务处理前被拒绝。
- Given 群聊用户请求修改个人模型密钥，When 路由，Then 操作被拒绝并提示转到私聊。
- Given 普通用户使用仅会员机器人，When 发消息，Then 不执行智能体。
- Given 用户解绑渠道，When 计划任务尝试推送，Then 不再发送到该渠道。

## 非功能要求

每个渠道有本地协议夹具；SDK 升级影响限制在适配模块；外部调用设置超时、重试上限和限流。

## 设计评审问题

- 渠道账号、渠道身份、求职用户和会话的关系如何建模？
- 平台要求快速确认回调时，异步处理如何保证最终响应？
- 主动推送应选择最近渠道、用户首选渠道还是全部渠道？

## 交付物

两个渠道适配器、账号与绑定管理、范围权限、媒体处理、平台模拟测试、端到端演示和运维说明。
