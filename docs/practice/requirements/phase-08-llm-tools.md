# 第 08 期：LLM 调用层与工具执行

**依赖**：第 07 期  
**目标**：统一同步与流式模型调用，并实现可审计、可限制的工具调用循环。

## 业务背景

不同业务智能体都需要构建 Prompt、调用模型、处理流式响应和执行工具。如果这些逻辑散落在智能体中，会导致行为不一致、难以测试和难以控制副作用。

## 用户故事

- 作为智能体开发者，我能通过一个稳定接口完成同步或流式调用。
- 作为智能体，我能声明可用工具，让模型在需要时调用。
- 作为用户，我能区分正文、思考状态、工具调用和工具结果。
- 作为安全负责人，我能限制高风险工具并追踪调用原因和结果。

## 业务规则

1. 调用层负责模型解析、Prompt 组装、超时、取消、错误归一化和响应分片。
2. 工具使用结构化输入与输出，并有唯一名称、用途说明和参数校验。
3. 单次请求限制工具循环次数、总耗时和输出大小，达到限制后正常终止并解释原因。
4. 有副作用的工具必须检查当前用户权限；敏感参数和结果不得完整写入日志。
5. 工具异常作为受控结果返回模型或用户，不能让流无结束地挂起。
6. 同步与流式调用应保持相同业务语义；取消客户端请求后，应尽力中止下游调用。
7. 提供假模型和假工具，能复现不调用工具、调用一次、连续调用、参数非法和超时场景。

## 范围外

多 Agent 协作、长期记忆、动态工具搜索和任意 Shell 执行。

## 验收场景

- Given 假模型直接回答，When 同步与流式调用，Then 最终正文语义一致。
- Given 假模型请求一个只读工具，When 参数合法，Then 工具执行一次并把结果交回模型。
- Given 模型持续请求工具，When 达到循环上限，Then 请求可控结束并记录原因。
- Given 普通用户请求管理员工具，When 权限检查，Then 工具不执行且返回无权限结果。
- Given 客户端取消流式请求，When 下游仍在生成，Then 资源在限定时间内释放。

## 非功能要求

每次调用有请求 ID；日志可重建调用顺序；工具参数校验失败不进入实现；模块测试不访问公网。

## 设计评审问题

- Prompt 拼装属于调用层还是业务智能体？哪些部分稳定，哪些部分可变？
- 工具返回错误与抛异常分别用于什么场景？
- 如何避免模型通过文本绕过工具权限？

## 交付物

LLM 调用接口、同步与流式实现、工具契约、执行循环、权限与限额、假模型测试和协议说明。
